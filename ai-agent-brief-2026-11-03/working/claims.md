# Claims

- c01: x402 PR #4080 (merged 2026-11-02) fixes the Python SIWX extension's nonce-replay check, which issue #4079 (covered in the 2026-11-02 edition) found was never actually running because `hooks.py` checked for a nonexistent `has_record_nonce` method instead of the documented `record_nonce`.
- c02: x402 PR #4082 (merged 2026-11-02) fixes the Go facilitator's V2 abort path, which issue #4081 (covered in the 2026-11-02 edition) found dropped a hook's diagnostic `Message` on both `Verify` and `Settle`, restoring parity with the V1 branch and the server-side V2 handling.
- c03: In the same 48-hour window, x402 also merged PR #4088 (adds an `RPCURL`/`RPCByChainID` option to the Go batch-settlement client so gas-sponsoring extensions work with a non-RPC-backed signer) and PR #4096 (removes a Go `ProcessPaymentRequest` stub that always returned "not implemented"), then PR #4102 cleaned up five lines of restated test comments across all four merges — evidence of a coordinated review sweep, not four unrelated fixes.
- c04: x402 PR #4033 (merged 2026-11-02) fixes the Python SDK's SVM (Solana) signer, which issue #4032 (filed 2026-10-28) found reported a confirmed or finalized on-chain transaction failure as a successful settlement, instead of returning `transaction_failed`.
- c05: mppx PR #1157 (merged 2026-11-02) adds an opt-in `replay` recovery option to `mppx/proxy`, fixing issue #1044 (filed 2026-10-14): a payment settles, the upstream request is forwarded bound to the client's connection, and if the client disconnects before a long-running job finishes (the report cites a 2-4 minute Seedance video-generation call hitting a 524 timeout), the payer has no way to collect what they paid for — a same-credential retry is rejected as replay, a new-credential retry charges again.
- c06: Across the three fixed defects, the common thread is not a single root cause but three distinct classes of bug (a capability-name mismatch, a cross-language parity gap, and a payment/delivery-state handling gap) surfacing in the same two protocols within the same short window — read as a sign of rising scrutiny on these codebases' correctness, not of one systemic flaw.
