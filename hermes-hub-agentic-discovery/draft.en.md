## Abstract

Hermes Hub describes itself as an open-source marketplace — "the work board where AI agents get hired and paid"[^s01][^s03]. Its key distinction is that it is built on top of an emerging industry standard, **Agentic Resource Discovery (ARD)** — a v0.9 draft specification published in May 2026 by authors at Google, Microsoft, and Hugging Face that standardizes how an AI client discovers, before invocation, "what is available for this task"[^s05][^s06][^s08]. Hermes Hub declares capabilities via the Hermes Capability Taxonomy (340 capabilities across 28 domains), exposes `urn:air` identifiers and `/.well-known/ai-catalog.json`, and combines Ed25519-signed bids with Stripe-based MPP/Link settlement (crypto x402 is Phase 2)[^s03][^s04]. This report makes two things explicit, however: (1) almost every Hermes-Hub-specific fact rests on its own primary docs, with essentially no independent third-party verification or adoption data; and (2) the "Hermes Agent by Nous Research" association implied by the repo description is community-level interoperability via open standards rather than an official partnership, and the product itself is a general ARD work board[^s02][^s03][^s10][^s16].

## Introduction

Hermes Hub is presented, via its official site and GitHub repository (amanning3390/hermeshub), as "an ARD-compatible marketplace that enables AI agents to find work and receive payment"[^s01][^s02]. The basic flow: a requester posts work, capable agents discover it through the open ARD standard, submit Ed25519-signed bids, and settle over Stripe MPP/Link/x402 rails[^s01][^s03].

This report dissects Hermes Hub's technical structure from the three primary sources the user supplied — the official site, the GitHub repo, and the underlying `agenticresourcediscovery.org` specification. Because both sites are client-rendered SPAs whose content is thin under static fetching, the body relies mainly on the repo README, the machine-readable catalog (`ai-catalog.json`), and the ARD spec's primary text.

One important caution: the name "Hermes" overlaps with a separate open-source agent, Nous Research's "Hermes Agent"[^s10][^s11]. As §6 shows, the two are related only by community-level compatibility through open standards, with no official partnership confirmed, so "Hermes Hub" here refers solely to the ARD work board pointed to by the amanning3390 repository.

## Background — The Agentic Resource Discovery (ARD) Protocol

Understanding Hermes Hub requires first looking at its foundation, ARD. The spec "defines how AI artifacts are cataloged, discovered, and searched across federated networks"[^s05], where an artifact is any "external capability an AI client can call on to do a task — an agent, MCP server, Skill, API, or workflow"[^s06].

ARD's design principle is a sharp boundary. It "sits entirely before invocation," helping the client find the right resource while the resource is invoked through its own native mechanism[^s06]. It is therefore not an execution runtime (not MCP, A2A, Skills, or an API runtime) and not a centralized catalog — it presumes many decentralized discovery services, each with its own governance, trust, and ranking policies[^s06]. The flow is five steps: "publish an `ai-catalog.json` at a well-known path on your domain → registries crawl it → an agent searches by intent → it verifies the publisher → then it connects"[^s06]. Identifiers follow `urn:air:<publisher>:<namespace>:<name>`, and the `<publisher>` must be a verifiable FQDN, anchoring trust without central registration[^s05].

ARD's status must also be clear. It is a **v0.9 Draft (Proposal)** dated 28 May 2026, authored by Junjie Bu (Google), R.V. Guha (Microsoft), and Shaun Smith (Hugging Face)[^s05]. Independent reporting says eleven companies — including Google, Microsoft, GitHub, and Hugging Face, with Nvidia, Salesforce, and Snowflake also contributing — have published ARD[^s08], and Hugging Face's Discover tool is offered as the reference implementation[^s07]. Adoption is still early, though: one independent analysis noted that three days after the spec dropped, Hugging Face was the only one of the 11 launch companies serving an actual catalog at `/.well-known/ai-catalog.json` on its main domain[^s09].

## Hermes Hub Architecture and Features

Hermes Hub is one marketplace that implements this ARD standard. Workers declare what they can do via the **Hermes Capability Taxonomy (HCT)** — per the README, "340 machine-readable capabilities across 28 domains," exposed at `/.well-known/ai-catalog.json`[^s03]. The deployed catalog declares `specVersion: "1.0"`, host `did:web:hermeshub.xyz`, and three URN entries including `urn:air:hermeshub.xyz:registry:capabilities` ("340+ capabilities across 28 domains")[^s04].

Identity and bidding are handled cryptographically. Anonymous sign-in mints a `urn:air` identifier and an Ed25519 keypair whose private key is held client-side to sign bids and declarations _(unverified — single source)_[^s02]. Bids are "Ed25519-signed and verified server-side," and "awards snapshot the platform fee at award time so later fee changes never apply retroactively"[^s03]. Every agent, work request, and catalog entry uses an RFC 8141 `urn:air:<publisher>:<namespace>:<name>` URN[^s03].

The tech stack is a conventional serverless web setup. The frontend is a Vite + React + TypeScript SPA (hash routing, Tanstack Query, shadcn/ui, Tailwind); the backend is Vercel serverless functions with Neon Postgres (Drizzle ORM, 16 tables); the repo is 96.7% TypeScript[^s02]. Hermes Hub also states that it federates with other ARD registries (GitHub Agent Finder, Hugging Face Discover) so workers reach the whole ecosystem, not just one catalog[^s03].

## Payment and Settlement Rails

Settlement comes in two tracks. Unattended agent-to-agent settlement uses **MPP (Machine Payments Protocol)**, which the README describes as "unattended agent-to-agent settlement via PaymentIntent + HTTP 402"[^s03]. Human-supervised flows go through **Stripe Link/Checkout**[^s03]. "MPP" here reads less like a separately ratified external spec and more like Hermes Hub's own label for its Stripe-based settlement; this report reproduces it as the project states it _(vendor-defined)_.

Crypto rails are roadmap-stage. The README and site say "crypto rails (x402) are Phase 2," with on-chain USDC settlement on Base/Solana on the roadmap under the same signed-bid, fee-snapshot guarantees[^s03][^s01]. For context, x402 is a real open payment protocol built by Coinbase that embeds stablecoin payments into HTTP using the 402 status code, later donated to the x402 Foundation at the Linux Foundation[^s13][^s14]. Finally, on pricing, the first 500 workers ("Founder-500") lock in a 1.5% lifetime fee versus the 5% standard[^s01][^s03].

## Identity and Relationship Analysis

The first obstacle when researching Hermes Hub is an identity confusion. The GitHub repo's description labels the project "HermesHub - The Skills Hub for Hermes Agent by Nous Research. Browse, share, and install community skills"[^s02]. Yet the product README and official site describe the same project as "an ARD work board where AI agents get hired and paid," with no mention of Nous Research[^s01][^s03]. A third-party aggregator (Hermes Atlas) follows the repo description, classifying it under "Hermes Agent Skills & Skill Registries"[^s12]. Because the two self-descriptions conflict, this report presents both rather than resolving them.

The accurate relationship is "community compatibility intended, but not an official partnership." On one hand, Nous Research's "Hermes Agent" is a distinct open-source self-improving agent that runs on a personal server, installs skills from `agentskills.io`, and ships under MIT — with no mention in its primary docs of "Hermes Hub" or `amanning3390`, and the Hermes Hub README does not mention Nous Research either[^s10][^s11][^s03]. On the other hand, amanning3390 also publishes companion tooling that wires into HermesHub — `hermes-ard-capabilities` ("a drop-in skill + CLI for agents to publish ARD-compliant ai-catalog.json and interact with HermesHub")[^s15] and a `hermes-workspace` skill that targets Nous's Hermes Agent but explicitly depends on a community fork (`outsourc-e/hermes-agent`) rather than the upstream repo[^s16]. So Hermes Hub is a **community project designed to interoperate with** Nous's Hermes Agent through open standards (agentskills.io, ARD) — not an official or endorsed Nous Research product, and the product itself is reframed as a general ARD work board _(interpretive)_[^s03][^s16].

## Discussion — Assessing Maturity and Verifiability

Hermes Hub's technical design is itself coherent and standard-conformant. It faithfully follows ARD's `urn:air` / well-known-catalog / federation model[^s04][^s05], and devices like Ed25519 signing, client-held keys, and fee snapshots are reasonable pieces for an agent marketplace[^s03]. Putting an external payment standard like x402 on the roadmap also aligns with where the ecosystem is heading[^s13].

On verifiability, though, there is a clear limit. Almost every Hermes-Hub-specific fact — capability counts, signature verification, settlement behavior, user numbers — is confirmable only from the project's own sources (site, README, catalog); no independent third-party audit or adoption/usage data was found _(interpretive)_. The underlying ARD is likewise very early as a v0.9 draft, with Hugging Face essentially the only live registry[^s05][^s09]. The repo itself shows early-stage activity at the scale of tens of commits[^s02]. In short, Hermes Hub is best read as "a faithful early implementation of a promising industry standard," with insufficient independent evidence to treat it as proven production infrastructure.

## Limitations

- **Reliance on self-sourcing.** Hermes-Hub-specific facts rest almost entirely on the project's own site, README, and catalog. No independent audit, security review, or usage statistics were found.
- **Identity.** The repo's "Skills Hub for Hermes Agent by Nous Research" description superficially conflicts with the product's "ARD work board" framing. This report reconciles them as "community interoperability via open standards (not an official partnership)," but could not obtain confirmation from Nous Research.
- **Version inconsistency.** The README cites ARD v0.9 while the deployed `ai-catalog.json` declares `specVersion 1.0`; which the live deployment honors was not verified.
- **Status of MPP.** "Machine Payments Protocol" appears to be Hermes Hub's label for its Stripe-based settlement rather than an external standard, and is reproduced as the project describes it.
- **A fast-moving target.** Repo metrics (293 stars, 98 forks, 67 commits) and the spec/roadmap are as of 2026-06-29 and will drift.
