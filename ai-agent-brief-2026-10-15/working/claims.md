# Claims

- c01: On October 14, 2026, the x402 Technical Steering Committee published a draft proposal (PR #3801) for a formal protocol-change process — Design Principles plus "XPs" (x402 Proposals) — modeled on MCP's Design Principles and SEP guidelines, moving x402 governance from ad hoc PRs toward a documented, TSC-reviewed process.
- c02: The XP draft specifies four proposal types (Standards, Extensions, Process, Informational), requires conformance tests before a Standards Track XP can finalize, and marks an XP dormant if it has no sponsor after six months — concrete process mechanics, not just an announcement of intent.
- c03: On October 14, 2026, a third-party "UTA Trust Kit" — Ed25519-based middleware implementing Agent Trust Cards (ATC/1.0) for Express and FastAPI — was submitted to x402's third-party-extensions registry, with a live reference API on Base Sepolia testnet and four real on-chain EIP-3009 settlements, giving x402 resource servers a mechanism to verify a calling agent's identity and solvency before serving a request.
- c04: On October 14, 2026, Google published documentation for MCP support in Apigee hybrid (available since hybrid release 1.17.0, shipped September 14, 2026), letting an operator turn an existing OpenAPI 3.0.x-described API into MCP tools discoverable by agents, with the MCP runtime and traffic confined to the operator's own Kubernetes cluster and access scoped through existing Apigee API products.
- c05 (why it matters): Of the seven protocols this beat tracks by name (x402, AP2, ACP, UCP, MPP, L402, Trusted Agent Protocol), only x402 produced visible activity in this window — both a governance proposal and a third-party identity/trust extension — while AP2's GitHub history shows no commits since April 29, 2026 and Visa's Trusted Agent Protocol sample repo has had no commits since October 28, 2025, consistent with a pattern (also noted in the October 14 brief) of standards work concentrating in one protocol while the others stay dormant.
