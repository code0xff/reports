Deepsearch 하니스로 생성한 리서치 보고서.

발행일 2026-10-15 태그 — 상태 ready

초록

x402 기술운영위원회(TSC)가 10월 14일 올린 초안은 프로토콜에 처음으로 제대로 된 거버넌스를 부여하려는 시도다. 제안 유형, 적합성 테스트, 6개월 휴면 규정까지 — 상당 부분을 Model Context Protocol(MCP)의 프로세스에서 그대로 가져왔다[1]. 같은 날 한 외부 개발자는 x402 확장 레지스트리에 미들웨어 등록 PR을 올렸다. 판매자가 요청을 처리하기 전에 호출자가 누구인지 암호학적으로 확인할 수 있게 하는 도구로, Ed25519로 검증하는 Agent Trust Card를 쓰며 테스트넷에는 이미 실제 정산 4건이 기록돼 있다[2]. 구글은 별도로 Apigee hybrid 안에서 기존 API를 에이전트가 호출 가능한 도구로 바꾸는 방법을 문서화했는데, 이때 도구 트래픽은 운영자 자신의 클러스터를 벗어나지 않는다[3]. 이번 주기 활동 중 결제 자체를 건드린 것은 없다. 누가 호출하고 있는지, 그 호출 규칙이 문서로 남아 있는지가 이번 주기의 화두였다.

서론

이번 호는 2026년 10월 12일부터 10월 15일까지를 다룬다. 결제 레일 쪽 배경지식은 사이트의 에이전트 커머스 프로토콜 비교와 x402 프로토콜 심층 분석에 있다. 10월 14일 호는 거의 정적인 분위기로 끝났다. Shopify와 구글은 제품을 출시했고, Pluto Security는 그 결과를 감시할 자금을 모았으며, 추적 중인 결제 스펙들은 병합되지 않은 PR 하나 외에는 아무것도 내놓지 않았다. 이번 창에서도 그 비대칭은 그대로다. 추적 대상 7개 스펙(x402, AP2, ACP, UCP, MPP, L402, Trusted Agent Protocol) 중 가시적으로 움직인 곳은 여전히 x402뿐이다. 다만 이번 움직임은 결제보다 한 층 위에 있다. 결제 메커니즘 자체는 이번 창에서 바뀌지 않았고, 그 위에 거버넌스와 신뢰 인프라가 쌓였다.

이번 주기에 있었던 일

x402, MCP에서 빌려온 정식 변경 프로세스 초안 작성

x402 기술운영위원회는 10월 14일 출범 이래 없었던 거버넌스 구조를 제안하는 초안 PR을 올렸다[1]. "단순함이 완전함보다 우선한다", "입증된 필요가 예상된 필요보다 우선한다" 같은 TSC 소유의 원칙인 "Design Principles"와, 프로토콜 변경을 위한 공식 트랙인 "XP"(x402 Proposal)를 도입한다. XP는 네 가지 유형(Standards, Extensions, Process, Informational)으로 나뉘고 전용 디렉터리 specs/xps/에 보관되며, TSC가 2주마다 검토하고, 6개월 안에 후원자가 나서지 않으면 휴면으로 분류된다. Standards Track XP는 적합성 테스트 없이는 확정될 수 없다. 모델은 명시적이다. 제안서 자체가 MCP의 Design Principles와 SEP 가이드라인을 템플릿으로 인용한다. 매주 수십 건의 임의 PR을 받아들여 온 스펙 저장소(이 브리프가 9월부터 추적해 온 패턴)에게, 번호가 붙고 후원자가 있고 기한이 정해진 제안 트랙은 다른 종류의 변화다. 다음에 무엇을 바꿀지가 아니라 결정을 어떻게 내릴지를 위원회가 정하는 일이다. 이 PR은 논의용 초안일 뿐 확정된 프로세스가 아니며 병합 일정도 없다.

외부 키트가 x402 판매자에게 에이전트 신원 확인을 가져오다

같은 10월 14일, 한 개발자가 x402의 서드파티 확장 레지스트리에 "UTA Trust Kit"을 추가하는 PR을 올렸다. Express와 FastAPI용 Apache-2.0 미들웨어로, 리소스 서버가 요청을 처리하기 전에 호출 측 에이전트를 검증할 수 있게 한다[2]. 방식은 Ed25519 서명으로 확인하는 Agent Trust Card(ATC/1.0)이며, 에이전트의 신원·지불능력·위험 신호를 다룬다. 제출물은 Base Sepolia 테스트넷의 실시간 레퍼런스 API를 가리키는데, 검증 1건당 0.01 USDC로 가격이 매겨져 있고 x402.org 퍼실리테이터를 통해 정산되며, 체인 위에는 이미 EIP-3009 기반 실제 정산 4건이 기록돼 있다. 명명된 프로토콜들(AP2의 위임 체인, Visa의 Trusted Agent Protocol)이 각자 겨냥했던 바로 그 하위 분야 — 에이전트 신원과 권한 — 가 정작 그 표준 기구들이 아니라 무관한 외부 기여자가 x402에 붙인 확장으로 등장한 셈이다. 아직 한 명의 기여자가 올린 PR 한 건일 뿐 병합되지 않았고, 체인상 정산 기록도 제출자 외에는 아무도 독립적으로 확인하지 않았다.

구글, Apigee hybrid 내 MCP 지원을 문서화

구글은 10월 14일 Apigee hybrid의 MCP 지원 문서를 공개했다. 실제로는 한 달 전인 hybrid 1.17.0 릴리스에서 이미 출시된 기능이다[3]. 작동 방식은 간단하다. 기존 OpenAPI 3.0.x 스펙을 지정하면 그 안의 각 오퍼레이션이 에이전트가 발견하고 호출할 수 있는 MCP 도구가 된다. MCP 서버 코드를 따로 작성할 필요가 없다. 트래픽은 구글이 운영하는 중개 서버를 거치지 않고 운영자 자신의 쿠버네티스 클러스터 안에 머물며, 접근 권한은 Apigee 고객이 이미 사람용 API 키를 통제하던 API 제품 체계로 그대로 범위를 잡는다. 앞의 두 사례보다 작은 이야기다. 새로운 프로토콜 결정은 없고, 벡터가 몇 주 전 조용히 내놓은 기능을 뒤늦게 문서화한 것뿐이다. 그래도 넣을 만한 이유는 있다. 두 호 전 Pluto Security의 세일즈 포인트와 같은 본능이기 때문이다. 에이전트 접근을 위해 별도의 체계를 새로 짜는 대신, 이미 있는 접근 통제 체계 안으로 끌어들이는 것이다.

왜 중요한가

x402의 두 사례는 같은 방향을 가리킨다. 1년 동안 결제 레일 기능을 쌓아 온 프로토콜이 이제는 그 기능을 누가 결정할지, 그리고 누가 그 기능을 호출할 자격을 가질지에 힘을 쓰고 있다. 외부 기여자를 끌어들일 만큼 채택이 진행된 인프라라면 자연스러운 성숙 과정이고, x402는 분명 그 단계에 있다(이전 호에서 다뤘듯 리눅스 재단과 연계된 거버넌스 기구에 약 40개 회원 조직이 있다). AP2, ACP, UCP, MPP, Trusted Agent Protocol은 분명 그렇지 않아 보인다. AP2의 깃허브 기록에는 2026년 4월 29일 이후 병합된 커밋이 없다[4]. Visa의 Trusted Agent Protocol 샘플 저장소는 2025년 10월 28일 이후 커밋이 없다[5]. 적극적으로 거버넌스를 운영하고 적극적으로 확장되는 프로토콜 하나와 조용한 여섯 개 사이의 격차는 이제 일주일짜리 관찰이 아니다. 이 브리프 최소 다섯 호에 걸쳐 유지되고 있다.

지켜볼 신호

  • x402 XP 제안이 확정되는지, 수정되는지, 10월의 배송 영수증 확장안처럼 그냥 멈추는지.
  • UTA Trust Kit의 두 번째 통합 사례, 또는 테스트넷이 아니라 실제 운영 환경에 배포하는 x402 리소스 서버의 등장.
  • x402의 두 사례에 대한 독립적인 보도. 지금까지는 둘 다 깃허브 PR 자체에만 의존하고 있다.
  • AP2, ACP, UCP, MPP, L402, Trusted Agent Protocol 중 어디서든 커밋 하나라도 나오는지. 나온다면 AP2 단독으로만 벌써 6개월째 이어지는 휴면 패턴이 깨지는 셈이다.

한계

x402 관련 두 항목 모두 작성 시점에서 병합되지 않은 오픈 PR이며, 독립적인 언론 보도가 없고 크게 수정되거나 폐기될 수 있다. UTA Trust Kit의 기술적 주장 — Ed25519 검증, 체인상 정산 4건 — 은 제출자 본인의 설명이며 독립적으로 감사되지 않았다. Apigee 항목은 이번 창보다 한 달 앞서 출시된 기능의 문서화를 다룬 것으로, 포함한 이유는 글의 발행일 때문이지 새 릴리스 때문이 아니다. "AP2와 Trusted Agent Protocol이 휴면 상태"라는 해석은 두 공개 저장소의 커밋 기록을 샘플링한 결과이며, 두 조직의 비공개 작업까지 포괄하는 전면 조사는 아니다. 이번 창에서는 피드, 웹 검색, 깃허브 레인 모두 접근 가능했다. 논문 레인은 돌리지 않았는데, 범위 안에서 새로운 학술 결과를 가리키는 것이 없었기 때문이다. X와 LinkedIn은 정책상 직접 읽지 않았고, 이번 창에서 둘 중 어느 쪽도 출처로 추적되지 않았다.
