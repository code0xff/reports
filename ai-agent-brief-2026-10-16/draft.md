## Abstract

Google added DPoP key-binding for OAuth refresh tokens on October 15, and wrote the multi-agent case directly into the spec guidance: an intermediate agent exchanges an upstream token through Cloud STS for one bound to its own key, instead of ever touching another agent's private key[^s01]. Figma used its first Config event in India, on October 14, to widen its agent-on-canvas rollout and push Figma MCP past 20 third-party tool integrations[^s02]. At Stripe's Monetize 2026 conference, recapped October 13, companies building on agent work described abandoning flat subscription pricing because agent runtimes stopped fitting a flat price. Replit's 25-cent-per-checkpoint charge broke once checkpoints started costing several dollars to run[^s03]. And an OpenAI customer, Third Moment Research, published a description of running up to 10,000 agents at once for 36 to 48 hours per investigation[^s04]. None of this is a payment protocol shipping. It is the infrastructure one layer beneath payment protocols: who an agent is, what it can call, and what it costs to run, getting worked out while x402 remains the only one of the seven tracked specs still showing activity, and even that activity this window is the same open pull request the prior edition already covered[^s05][^s06].

## Introduction

This edition covers **2026-10-13 through 2026-10-16**. Background on the payment-rail side of this beat lives in the site's [agent commerce protocol comparison](../agent-commerce-protocol/) and [x402 protocol deep dive](../x402-protocol/). The last several editions have tracked one durable asymmetry: x402 keeps producing governance and extension activity while AP2, ACP, UCP, MPP, L402, and Trusted Agent Protocol sit idle. This window doesn't add a new payment-spec data point to that pattern — it adds a different one. The things that moved are the layers payment protocols assume already exist: an identity check before the payment, a design tool agents can act inside, a pricing model for what the agent did.

## What moved

### Google writes multi-agent delegation into its OAuth identity layer

Google's OAuth platform now supports DPoP (RFC 9449) for refresh tokens: a client-generated key pair binds the refresh token to a specific holder, so a stolen token is useless without the matching private key[^s01]. Access tokens stay ordinary bearer tokens, which keeps high-volume API calls cheap to verify. The part that matters for this beat is the multi-agent case Google wrote directly into the guidance: when one agent calls another, the intermediate agent is supposed to exchange the token it received through Cloud Security Token Service for a new token bound to its own key, rather than passing along the original holder's private key. Google's own Agent Gateway, inside the Gemini Enterprise Agent Platform, already uses DPoP this way to validate agent identity for Workspace's Context-Aware Access. It is a narrower answer than any of the named agent-identity efforts (AP2's mandate chain, Visa's Trusted Agent Protocol, the IETF's seven competing agent-identity drafts), built on fifteen-year-old OAuth infrastructure instead of a new spec, and so far it only has one implementation: Google's own stack. No outside platform has said it is adopting DPoP-bound delegation for its own agents.

### Figma pushes agent context and MCP integrations past private beta

At Config, its first event in India, Figma made its agent-on-canvas feature available to a wider set of users and said Figma MCP now connects to more than 20 third-party tools, including Open Code, Dia, Grok Bot, and Sarvam[^s02]. The company also shipped Figma Specs, a markdown editor for writing down a design system's rules in a form an agent can read, and opened code layers (design-to-code prototyping, in private beta since June) to a wider beta. These read as separate product-launch items on their own. Together, Figma is building the same kind of machine-readable context layer x402's extension registry is trying to build for payments (an Agent Trust Card verified over Ed25519, covered in the prior edition): a place where an agent can look up the rules before acting, instead of inferring them from a UI built for people.

### A Stripe-hosted conference shows how agent work actually gets billed

Stripe's recap of its second annual Monetize conference, posted October 13, pulled five patterns from how AI companies now price agent work[^s03]. The concrete example: Replit charged 25 cents per agent checkpoint when checkpoints ran for a few minutes. As agent runtimes grew, some checkpoints cost Replit several dollars to run while customers still paid the flat 25 cents, so Replit moved to usage-based billing and added a rate-limited free tier to keep the simple-subscription experience available. Fin, Intercom's support agent, went further: instead of charging per conversation, it now lets customers choose which outcome they're paying for (a resolved ticket, a qualified lead, a booked meeting) and draw down a shared credit pool against whichever outcomes actually happen. The recap also cites an outside analyst's count of 7,600 AI-generated pricing answers across six AI engines, finding one unnamed company's pricing described negatively in 88% of responses when its real pricing wasn't machine-readable. In its place the engines invented prices ranging from $100 to $2,400 a seat from secondhand sources, a 24x spread the analyst attributes to pricing pages written for people without a thought for agents reading the same page. This is a conference recap published by the host, not independent reporting, but the specifics (dollar figures, named companies, a repeatable methodology) are more concrete than most vendor framing. The predictability problem it names is not hypothetical: GitHub Copilot's own June 1 switch to usage-based billing set off an immediate backlash, with one Pro+ subscriber burning roughly 8% of a month's credits in two hours and another spending $6 on a single change request[^s07]. GitHub's fix was a budget cap that stops the agent cold at zero dollars remaining — denial of service standing in for a cost model nobody has made legible yet.

### An OpenAI customer describes running 10,000 agents for a day and a half

Third Moment Research, which OpenAI features as a customer, publishes a description of its own operation: investigations that run up to 10,000 agents concurrently for 36 to 48 hours, built on Codex and the GPT-6 model family[^s04]. One worked example: Codex analyzed its own backtesting pipeline, found that agents were burning tokens by repeatedly polling a slow backtest for completion, and deployed a caching fix that cut the backtest from roughly three hours to three to five minutes. The company's co-founder is quoted saying GPT-6.1 Sol "maintain[s] a coherent thread of computational research across days of compute without losing the plot." It's a single vendor-published customer story, and nobody outside OpenAI and Third Moment has verified the agent count or the runtime claims independently — but if the scale is real, it is a different order of agent orchestration than anything previously quantified in this beat.

## Why it matters

Every item this window sits one layer away from the payment rail itself: an identity check that runs before a payment, a canvas agents act inside before anything gets bought, a pricing model for the work an agent did instead of the money it moved. That is a different kind of quiet than last edition's. The named payment specs (AP2, ACP, UCP, MPP, L402, Trusted Agent Protocol) aren't producing payment-spec news because, as prior editions have tracked, most of them aren't shipping anything: AP2's GitHub history still shows no commit since April 29[^s05]. The infrastructure those specs assume, though, is moving in parallel: a verifiable agent identity, a context an agent can act inside, a bill that reflects what an agent actually did, all built by companies with no stake in any of the seven named specs. x402 is still the one payment spec with visible motion, and even that motion this window is the same governance pull request the prior edition already described, open and unmerged since October 14[^s06].

## Signals to watch

- A second identity platform adopting DPoP-bound delegation for agent-to-agent calls, which would turn Google's pattern into a convention rather than a one-vendor mechanism.
- Independent confirmation of Third Moment Research's agent count and runtimes — so far this rests entirely on OpenAI's own post.
- Whether Figma's MCP tool count keeps growing past this conference announcement, or stalls the way several x402 extensions have.
- Any commit activity from AP2, ACP, UCP, MPP, L402, or Trusted Agent Protocol — AP2's dormancy is now past five and a half months.
- Whether outcome-based and per-checkpoint agent pricing, as described by Replit and Fin, shows up outside the handful of companies Stripe chose to feature.

## Limitations

The DPoP item, the Third Moment Research item, and the Stripe conference recap are each a single vendor's own account of its own work, with no independent verification found for any of them. The 88%-negative-pricing and 24x-price-spread figures trace to one analyst's unpublished methodology, cited secondhand inside Stripe's post. Figma's feature rollout is reported by TechCrunch, independent trade press, but the underlying facts (the 20+ MCP tools, the beta-to-wider-availability transition) come from Figma's own announcement at the event. The "x402 is the only active payment spec" and "AP2 is dormant" readings repeat a pattern this brief has sampled across six editions now, from two public repositories, not an exhaustive audit of any organization's non-public work. Feeds, web search, and GitHub were all reachable this window; the papers lane was not run, since nothing in scope pointed to a new academic result. X and LinkedIn were not read directly, per standing policy, and nothing in this window traced back to either platform as an originating source.
