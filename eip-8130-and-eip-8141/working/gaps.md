# Gaps — EIP-8130과 EIP-8141

## 반복 1 (2026-09-15)

### 해소
- 두 EIP의 마크다운 원문을 ethereum/EIPs `master`에서 직접 받아 조항 단위로
  인용(s01, s02, s05, s06). 헤더·Abstract·Motivation·Specification·Rationale·
  Backwards Compatibility 전부 1차 사료.
- 렌더된 EIP 페이지로 상수·모드표·APPROVE·멤풀 정책 교차 확인(s03, s04).
- 두 제안의 원 토론 스레드(s07, s08).
- 표준화 현황: CFI(2026-03) → SFI(2026-08-27)(s10, s11), Base–이더리움 분기
  (s09).
- 노드 운영자 관점의 운영 부담(s11).

### 남은 갭 (Limitations로 수용)
1. **ACD 회의록 원문 미확인.** CFI·SFI 상태 변화는 2차 보도(s10, s11)로만
   확인했고 Ethereum Foundation의 ACD 노트나 회의 녹취를 직접 대조하지 못했다.
   s11은 CFI(3월) 시점, s10은 SFI(8월) 시점을 말하므로 서로 모순이 아니라
   시점 차이다. 본문에서 시점을 붙여 서술한다.
2. **8130 정식 컨트랙트 저장소 미독.** 8130 명세 스스로 "the repository is the
   source of truth"라며 `base` 조직의 `src/Keystore.sol`을 계약 내부의 권위로
   지목한다. 그 저장소를 읽지 않았으므로 키스토어 내부 동작·정확한 가스 값은
   본 리포트의 검증 범위 밖이다.
3. **구현체 부재 확인.** 두 제안 모두 Draft이고 클라이언트 구현 현황
   (geth/reth/besu 등)을 조사하지 않았다. "Base vibenet 데브넷에서 시험 중"은
   보도(s09) 한 건에 의존한다.
4. **63% 가스 절감 주장 미검증.** s09가 전하는 Base 측 주장이며 측정 방법·
   대상 전송 유형이 공개되지 않았다. 단일 출처로 표기한다.
5. **PANews 비판 분석 접근 실패.** "왜 EIP-8141이 Hegotá의 1순위가 되지
   못했는가"를 다룬 분석이 403으로 차단됐다. 8141에 대한 체계적 비판 분석을
   확보하지 못했고, 비판은 magicians 스레드(s08) 수준에 머문다.
6. **RIP-7560 계보 미추적.** 8141 저자 다수가 ERC-4337/RIP-7560 진영이지만
   RIP-7560과 8141의 관계를 1차 사료로 확인하지 않았다. 본문에서 계보를
   주장하지 않는다.
7. **8130의 L1 프로파일 실현 가능성 미평가.** 명세는 L1/L2 두 프로파일을
   제시하지만 L1 코어 개발자들이 L1 프로파일을 검토했다는 증거를 찾지 못했다.

### 출처 충돌
- 실질적 충돌 없음. s11의 "CFI, not a committed Hegotá deliverable"와 s10의
  "Scheduled for Inclusion"은 각각 2026-03과 2026-08 시점 서술이다. 본문은
  두 시점을 모두 적는다.

**판단: 갭 1~7 전부 Limitations로 이전 가능. 초안 진행.**
