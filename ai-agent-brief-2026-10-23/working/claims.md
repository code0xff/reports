# Claims

- c01: 1Password's new "1Password for Agents" feature lets a user approve a specific AI agent's login to a specific personal account without the agent ever receiving the underlying password, moving credential custody from "shared with the agent" to "brokered per-request by a third party the user already trusts."
- c02: 1Password's launch names six initial agent integrations (Claude Duet, OpenAI's Dots and ChatGPT Work, xAI's Grok Bot, Meta's Muse, and Town's agents) but does not describe any constraint on what an authenticated agent may do inside the account after login completes — the control is at the login boundary, not the session.
- c03: Google's Agent Compute Engine moves agent identity from an application-level claim to a hardware-rooted one: each microVM gets a SPIFFE-based cryptographic identity and short-lived credentials injected at egress, so the agent process itself never holds the long-lived secret.
- c04: Google frames its expanded Agent Gateway/Registry/Identity/Observability stack as closing a gap specific to agents — that they start, pause, and resume far more often than traditional services, which existing compute and governance assumed were long-lived.
- c05: Stripe's Money20/20 recap argues the unresolved problem in agentic payments is not payment authorization (an agent having a credential) but intent authorization (what the consumer specifically asked for) — a gap neither Stripe's own spend-request proposal nor Amex's earlier-instruction approach has closed industry-wide.
- c06 (why it matters): Taken together, the three items show the agent-authorization problem resolving into three separate layers — account access (1Password), compute/process identity (Google), and transaction intent (Stripe) — each getting its own point solution rather than a shared standard spanning all three.
