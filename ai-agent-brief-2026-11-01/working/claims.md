# Claims

- c01: x402's facilitator previously let a throwing advisory hook (`afterSettle`, `afterVerify`, `onVerifyFailure`, `onSettleFailure`) change the outcome of `verify()`/`settle()`, so a payment that had already executed on-chain could surface to the caller as a failed settlement; PR #3151 isolates these four hook loops so a throwing hook is logged and skipped instead, while the two gate hooks (`beforeVerify`, `beforeSettle`) still fail closed by design.
- c02: pay-kit's routine Rust dependency re-pin (PR #407, bumping `solana-keychain` and the surfpool/litesvm test stack) changed `surfpool`'s default commitment handling, which broke the TypeScript charge/subscription servers' cross-client conformance tests against the Rust client because the TS servers never set `preflightCommitment` explicitly (PR #408) — a latent mismatch that a dependency bump, not a protocol change, exposed.
- c03: mppx merged two community-authored bug fixes (PRs #1139, #1140) that had sat open as #1101 and #1100 for roughly three to four weeks before a different contributor rebased and landed them, fixing a cooperative session-close bug that could cancel an unrelated close request and a payment-retry bug that could silently drop a POST body on retry.
- c04: Universal Commerce Protocol's PR #998 lets a business resolve a JWT authorization grant to an existing account by email, but only when the business has independently verified the issuer is the mailbox authority for that domain — and the PR's own security-considerations text names the residual risk (address recycling and reassignment) that this exception accepts.
- c05: A tampered build (v2.1.313) of Anthropic's Claude Code extension, published under Anthropic's own verified account on Cursor's extension marketplace, ran for about 11 hours on 2026-10-29 and attempted to add an attacker-controlled SSH key and open a reverse tunnel on installed machines, before Anthropic shipped v2.1.314 removing the payload; neither company has disclosed how the verified account was compromised.
- c06: Across this window's five items, the failure mode is the same shape — a verification or trust mechanism (an advisory hook, a commitment-level default, a Request object's retained state, an identity grant's issuer check, a marketplace publisher signature) silently stopped enforcing the guarantee it existed for, in systems whose actions (settling a payment, authorizing an account, installing a dev-tool update) are not easily reversible once taken.
