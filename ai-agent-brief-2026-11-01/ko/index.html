AI 에이전트, 개발자 도구, 에이전트 결제 — 데일리 브리핑, 2026-11-01

저장소 다섯 곳에서, 지켜야 할 규칙을 조용히 더는 지키지 않게 된 검증 장치 다섯 가지가 드러났다.

발행일 2026-11-01 태그 — 상태 ready

초록

이번 주기에 프로토콜 자체가 깨진 사례는 없다. 다섯 번 모두 깨진 것은 그 아래에서 뭔가 잘못됐을 때 알아채야 할 장치 쪽이었다. x402 facilitator는 예외를 던지는 훅 하나 때문에 이미 체인에 기록된 결제를 오류 메시지로 바꿔버릴 수 있었다[1]. pay-kit에서는 평범한 Rust 의존성 업데이트가 솔라나 커밋먼트 기본값을 슬쩍 바꿔버려서, 같은 프로젝트의 TypeScript 서버가 자기네 Rust 클라이언트와 맞지 않게 됐다[2][3]. mppx의 버그 수정 두 건은 3~4주째 머지되지 않은 채 묻혀 있다가 다른 사람이 집어 들었다[4][5]. Universal Commerce Protocol은 신원 연결 예외 조항을 하나 추가하면서, 그 조항이 남기는 잔존 위험을 같은 문장에서 명시했다[6]. 그리고 Anthropic의 Claude Code 확장 프로그램은 Anthropic 본인의 인증된 계정으로 배포된 변조 빌드가 Cursor 마켓플레이스에서 약 11시간 동안 SSH 백도어를 심은 채 살아 있었다[7].

서론

이번 호는 2026년 10월 29일부터 11월 1일까지를 다룬다. 결제 레일 전반의 배경은 사이트의 에이전트 커머스 프로토콜 비교 리포트를 참고하면 된다. 저장소를 넘나드는 버그 추적 흐름은 10월 31일 호에서 이어지는데, 그 호는 x402의 transaction-v1 시리즈 완결과 mppx의 타이밍 수정 두 건이 몇 시간 차이로 머지되며 끝났다.

이번 주기에 있었던 일

x402, 예외를 던지는 훅이 완료된 결제를 오류로 보이게 만드는 문제를 막다

x402 facilitator는 검증과 정산 과정에서 "advisory" 훅 네 개(afterVerify, afterSettle, onVerifyFailure, onSettleFailure)를 돌리고, 그 앞에 결제를 막을 권한이 있는 "gate" 훅 두 개를 둔다. advisory 훅에는 그런 권한이 없어야 하는데, PR #3151(2026-10-30 머지) 이전에는 있었다. afterSettle 훅이 예외를 던지면 실제 정산 실패를 처리하는 것과 같은 catch 블록으로 떨어졌고, 그 결과 돈은 이미 체인에서 움직였는데도 호출자에게는 오류가 보였다[1]. onVerifyFailure나 onSettleFailure 훅이 예외를 던지면 같은 루프의 뒤에 있는 훅들이 아예 실행되지 않아, 정상적인 복구 경로까지 막혔다. 수정은 네 루프 모두를 감싸서 예외를 던진 훅을 새로 만든 warnFacilitatorHookFailure 헬퍼로 기록하고 건너뛰게 했고, gate 훅 두 개는 기존대로 결제를 막는 쪽으로 계속 닫혀 있다[1][2]. x402의 리소스 서버 쪽은 이미 자체 advisory 훅을 이런 식으로 분리해둔 상태였다. 이번 PR은 같은 틈을 facilitator 쪽에서 닫은 것으로, 해당 이슈가 열린 지 1년도 더 지난 뒤다.

pay-kit, Rust 의존성 하나 올렸다가 자기 TypeScript 서버가 자기 Rust 클라이언트와 안 맞게 되다

PR #407은 pay-kit의 solana-keychain 의존성을 최신 커밋으로 다시 고정하면서 litesvm, surfpool-sdk, solana-message, wincode 버전까지 줄줄이 끌어올렸다. PR 설명에는 "소스 변경 없음"이라고 적혀 있었다[3]. 그런데도 pay-kit의 TypeScript 호환성 테스트가 깨졌다. 새로 올라온 surfpool 1.7이 그동안 TS의 charge·subscription 서버가 한 번도 설정한 적 없는 preflightCommitment 값을 실제로 적용하기 시작했고, 그래서 브로드캐스트 호출이 노드 기본값인 finalized로 떨어진 것이다. Rust 클라이언트는 아직 finalize되지 않은 confirmed 블록해시로 서명하기 때문에, preflight 단계에서 거부당했다[4]. 이 버그 자체는 새로 생긴 게 아니다. TS 서버는 원래부터 preflightCommitment를 명시하지 않고 돌아가고 있었다. 다만 세 단계 아래 의존성이 그동안 방치돼 있던 기본값을 갑자기 강제하기 전까지는 아무도 그 사실을 몰랐다. PR #408은 두 서버가 이미 사용하던 시뮬레이션 설정과 Rust 서버가 자신의 RPC 클라이언트에서 쓰던 설정에 맞춰 커밋먼트를 명시적으로 지정한다.

mppx, 몇 주째 묵혀 있던 수정 두 건을 그제야 머지하다

2026년 10월 29일에 머지된 PR #1139와 #1140은 각각 #1101, #1100이라는 멈춰 있던 커뮤니티 PR을 원작자 AkshatGada의 이름으로 다시 리베이스한 것이다. 3~4주 동안 손이 가지 않다가 다른 기여자가 집어 들었다. #1139는 세션 종료 버그를 고친다. mppx의 협조적 HTTP 세션 종료가 리소스 fetch가 쓰던 바로 그 Request 객체를 재사용했던 탓에, 리소스를 취소하면 전혀 관계없는 종료 요청까지 같이 취소될 수 있었고, 바디가 잠겨 있거나 이미 소비된 상태면 종료 요청 자체를 만들 수도 없었다[5]. #1140은 재시도 버그를 고친다. 402 챌린지 응답에 response.url이 채워져 있으면, mppx의 결제 재시도가 POST를 조용히 GET으로 바꿔버려 바디가 통째로 사라졌다[6]. 두 PR 모두 그대로 머지할 수 없었다. #1139는 그 사이 들어온 리다이렉트 처리 변경을 반영해야 했고, #1140은 라우트별 신원 기능 변경과 테스트용 의존성 고정 문제를 맞춰야 했다. 검증된 기여자가 올린 멀쩡한 수정 두 건이 며칠이 아니라 몇 주씩 걸려서야 들어간 이유가 아마 여기에 있을 것이다.

UCP, 신원 연결 예외를 허용하면서 같은 PR에서 그 위험을 스스로 적어두다

UCP의 신원 연결 규격은 지금까지 이메일만으로 계정을 연결하려면 DNS 위임이나 새로운 신원 공급자 관계가 필요했다. 2026-10-31에 머지된 PR #998은 더 좁은 예외를 하나 추가한다. 비즈니스가 토큰 발급자가 해당 이메일 도메인의 메일박스 권한자임을 독립적으로 확인했고, 발급자가 이메일을 인증됨으로 표시했고, 비즈니스 스스로 계정 주소를 검증했고, 충돌하는 연결이 없다면, 이메일만으로 기존 계정에 연결하는 것을 허용한다[7]. 한 번 연결되면 이후로는 발급자와 서브젝트 조합으로 계정을 찾기 때문에, 나중에 이메일이 바뀌어도 연결이 다시 바뀌지는 않는다. 이 PR의 보안 고려사항 항목은 기존의 "크로스 신원공급자" 위험 목록에 이 예외를 추가하면서, 받아들이는 위험을 스스로 적었다. 이메일 주소가 재활용되거나 다른 사람에게 재할당되면, 일정 조건에서 예전 연결을 그대로 물려받을 수 있다는 것이다.

Anthropic의 인증 계정이 Cursor 마켓플레이스에서 변조 빌드를 배포하다

Claude Code 확장 프로그램의 2.1.313 빌드가 Anthropic의 인증된 게시자 계정을 통해 Cursor 마켓플레이스에 올라가, 2026년 10월 29일부터 약 11시간 동안 그대로 떠 있었다. Anthropic은 이후 2.1.314로 교체했다[8]. Cursor에 따르면 이 코드는 설치된 기기의 authorized_keys에 공격자가 지정한 SSH 키를 추가하고 역방향 터널을 열려고 시도했다. Cursor는 관리자 권한이 없으면 SSH 단계 자체는 대개 실패했을 것이라고 밝혔지만, 키 추가와 지속성 시도는 권한 여부와 무관하게 일어날 수 있었다고도 덧붙였다. Cursor는 영향을 받은 사용자가 최대 5천 명이라고 밝혔는데, 이는 독립적으로 검증되지 않은 Cursor 자체 집계다. Anthropic의 입장은 선을 분명히 긋는다. "공격자가 Cursor 마켓플레이스에 대한 접근 권한을 이용해 Cursor 사용자를 겨냥한 변조된 확장 프로그램을 게시했다. 우리는 이 확장 프로그램의 제작, 게시, 호스팅에 관여하지 않았다"[8]. Anthropic의 인증된 계정으로 게시할 수 있게 만든 그 접근 경로를 어떻게 확보했는지는 양측 모두 아직 밝히지 않았다.

왜 중요한가

다섯 건을 나란히 놓고 보면, 뭔가를 엉성하게 만들어서 생긴 문제가 아니다. x402, pay-kit, mppx, UCP 모두 활발하게 테스트를 거치며 개발되고 있고, Anthropic이 직접 작성한 확장 프로그램 코드 자체에도 문제는 없었다. 문제는 각 실패가 어디에 자리하고 있었는가다. 바로 아래 시스템이 뭔가를 잘못했을 때 그걸 알아채야 할 계층, 또는 어떤 행동을 유효한 것으로 칠지 결정해야 할 계층이다. 관찰만 해야 할 advisory 훅이 결과 자체를 바꿔버렸다. 두 서버가 그동안 묵묵히 무시해온 커밋먼트 기본값이, 아무도 의도적으로 테스트해서가 아니라 무관한 의존성 업데이트 사슬 때문에 갑자기 강제됐다. 멀쩡한 수정 두 건이 누군가 눈치챌 때까지 몇 주를 기다렸다. 신원 연결 예외는 그 예외가 남기는 위험을 함께 적은 문서 안에서 허용됐다.

플러그인 마켓플레이스가 "이게 정말 그 업체가 배포한 것인가"를 답하는 유일한 장치인 게시자 서명이, 11시간 동안 변조된 빌드를 그대로 통과시켰다. 누군가 Anthropic의 인증된 계정처럼 행동할 수 있게 만든 경로는 양측 다 아직 설명하지 않았다. 이 중 어느 것도 통상적 의미의 프로토콜 결함은 아니다. 규칙을 지키는 시스템과, 예상하지 못한 무언가가 생기기 전까지만 규칙을 지키는 시스템 사이의 간극이다.

지켜볼 지점

  • Anthropic이나 Cursor의 계정 탈취 경로 공개 여부. 케빈 보몬트가 제기한 "교체 빌드가 기존 백도어 흔적을 지우지 않는다"는 주장의 진위도 함께.
  • UCP가 스스로 적어둔 주소 재활용 위험, 실제로 악용되는 사례가 나오는가.
  • pay-kit의 다음 의존성 업데이트. 커밋먼트 수준 불일치를 잡는 명시적 호환성 테스트가 머지 전에 생겼는가.
  • x402의 리소스 서버 쪽과 facilitator 쪽 훅 분리, 결국 하나의 구현으로 합쳐질지, 아니면 1년 간격으로 같은 버그를 따로 고치는 패턴이 계속될지.

한계

Mastercard Agent Pay, Visa Intelligent Commerce와 Trusted Agent Protocol, Stripe의 Agentic Commerce Protocol, PayPal Agent Ready 같은 카드 네트워크·PSP 에이전트 커머스 제품은 이번 주기에도 날짜가 명확한 1차 발표가 없었다. 다섯 호 연속이다. 이번 창에 해당하는 소식을 웹 검색으로 찾아봤지만 4월, 7월의 오래된 항목만 나왔다. AP2 저장소도 이번 창에 머지된 PR이 없었다. X나 LinkedIn 게시물로 거슬러 올라가는 항목은 없었다. Cursor·Anthropic 사건의 정확한 지속 시간은 매체마다 다르다(출처와 시간대 환산 방식에 따라 11~12시간으로 엇갈린다). 이 브리핑은 BankInfoSecurity가 제시한 수치를 가장 직접적으로 귀속된 설명으로 삼았다. 출처 여덟 건 중 여섯 건이 GitHub PR인데, 이는 각 프로젝트가 무엇을 바꿨는지에 대해서는 1차 자료지만 그 수정이 실제로 배포된 뒤에도 유효한지에 대해서는 아무것도 말해주지 않는다.
