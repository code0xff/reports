## 초록

브레이브(Brave) 검색 API가 API 키 발급 대신 x402 프로토콜로 요청마다 결제를 받기 시작했다[^s01][^s02]. 구글 클라우드는 Organization Policy MCP 서버를 정식 출시(GA)해, 자율 에이전트가 사람이 콘솔을 거치지 않고 클라우드 거버넌스 정책을 직접 읽고 쓸 수 있게 했다[^s03]. 그리고 이 브리프가 한 주째 추적해온 결제 스택 mppx는 viem 토큰과 지갑 주소를 같은 종류의 입력으로 다루는 통화(currency) 모델 재작성을 머지했다[^s04]. 검색 API, 클라우드 정책 엔진, 결제 SDK가 각자의 일정대로 — 에이전트가 직접 요청하는 쪽을 이제 설계의 기본값으로 삼기로 결정했다.

## 서론

이번 호는 **2026년 11월 10일부터 11월 13일까지**를 다룬다. 결제 레일 지형에 대한 배경은 이 사이트의 [에이전트 커머스 프로토콜 비교](../agent-commerce-protocol/)에, mppx의 세션 및 통화 설계는 [Machine Payments Protocol: spec and payment flows](../mpp-spec-and-payment-flows/)에 있다. 지난 호(2026-11-12)는 유나이티드항공의 제3자 에이전트 예약 차단, 구글 A2UI 1.0 출시, mppx의 ID 검증 우회 버그 수정을 다뤘다. 카드 네트워크와 AP2, UCP는 이번 주에도 머지되고 날짜가 확인된 변화를 내놓지 않았다 — 네 번째 연속으로 공백인데, UCP 저장소에는 이번 주 열려 있는 기능 PR이 열 건 넘게 쌓여 있는데도 그렇다.

## 무엇이 움직였나

### 브레이브 검색 API, x402로 요청당 결제를 받기 시작

에이전트가 답변의 근거로 쓰도록 만든 LLM Context 엔드포인트가, 이제 인증되지 않은 요청에 API 키를 요구하는 대신 HTTP 402를 돌려준다[^s01]. 응답에는 가격이 담겨 있고, 클라이언트는 베이스(Base) 체인에서 그 금액만큼 USDC 결제에 서명해 재요청하면, 결제가 확인된 뒤 검색이 실행되고 거래 영수증이 응답에 붙는다. 검증 단계는 제3자를 거치지 않고 브레이브가 자체 운영하는 결제 중계자(facilitator)가 처리한다. 글에서는 클라이언트 쪽 지갑으로 스트라이프(Stripe)가 만든 CLI 지갑 Purl을 추천한다[^s01].

이번 출시는 시범판이 아니라 실제 서비스지만, 제목만큼 넓지는 않다. 체인과 스테이블코인은 오늘 기준 베이스와 USDC뿐이고, 다른 체인은 "곧 추가될 예정"이라고만 적혀 있으며, 베이스에서의 가스비도 "한시적으로만" 보조된다[^s01]_(vendor-stated)_. 글은 웹·뉴스·이미지·영상·지역 검색 엔드포인트도 요청당 0.005달러의 x402 요율로 옮겨갈 것이라고 밝히는데, 이 서술은 미래 시제로 쓰여 있어 실제로 이미 적용됐는지는 확인되지 않는다. 브레이브는 바로 요청에 402 챌린지로 응답하는 You.com, 링크업(Linkup)과 같은 줄에 서게 됐다 — 제3자 리뷰에 따르면 엑사(Exa)와 패럴렐(Parallel)은 아직 API 키 방식을 쓴다. 이 소식이 올라온 HN 스레드에는 댓글이 하나도 없었는데, 이 브리프가 첫 호부터 추적해온 프로토콜에 주요 검색 브랜드가 결제 연동을 붙인 소식치고는, 그 자체로 눈에 띄는 침묵이다 — 당장 이걸 붙여 쓸 사람들에게조차 뉴스로 느껴지지 않았다는 뜻이다.

### 구글 클라우드, Organization Policy MCP 서버를 정식 출시

구글 클라우드는 2026년 11월 13일 Organization Policy MCP 서버의 정식 출시를 발표했다. "자율 에이전트와 파이프라인"이 콘솔이나 REST API를 손으로 거치지 않고 제약 목록 조회, 상속까지 반영된 유효 정책 읽기, 정책·커스텀 제약 생성 같은 도구를 직접 호출할 수 있다[^s03]. 함께 나온 기능으로, 관리자는 이제 제미니(Gemini)를 통해 자연어로 커스텀 제약을 작성할 수 있는데, 예시 두 가지가 에이전트를 직접 가리킨다 — Agent Runtime에 agent-identity를 요구하는 제약, 그리고 거기 배포되는 모든 에이전트가 승인된 Agent Gateway를 쓰도록 요구하는 제약이다[^s03].

이번에 나온 것은 배포 시점의 거버넌스이고, 실행 시점의 권한 부여가 아니다. 이 제약들은 에이전트가 가동되기 전에 어떻게 구성되고 식별되는지를 정할 뿐, 가동 중인 에이전트의 개별 호출이 무엇을 할 수 있는지는 건드리지 않는다 — 이쪽은 x401, FIDO의 에이전트 표준 작업, 옥타(Okta)의 Cross App Access처럼 이 주제를 다루는 신원·인가 표준들이 반대쪽에서 풀려는, 더 어렵고 더 논쟁적인 문제다. 구글의 MCP 서버가 눈에 띄는 지점은 클라우드 거버넌스 표면 자체를 에이전트가 호출할 수 있게 만들었다는 것이고, 이는 오늘 세 소식 전체에서 반복되는 전환("사람이 설정한다"에서 "에이전트가 설정한다"로의 이동)과 같은 결이다.

### mppx, 통화를 읽는 방식을 하나로 합치다

2026년 11월 12일 mppx에 머지된 PR #1275는 그동안 흩어져 있던 통화 처리 경로들을 하나의 `Currency` 타입으로 교체해, 원시 주소와 viem `Token`, `ResolvedToken`을 테포(Tempo) 클라이언트·서버, x402 자산 목록, EVM 서버 메서드 전역에서 같은 입력으로 받아들이게 한다[^s04]. 이로써 막힌 구체적인 버그는 이렇다. 변경 전에는 토큰의 소수점 자릿수를 토큰 자체에서 읽지 않고 가정해야 했으므로, 다른 체인에서 온 토큰이 조용히 잘못된 스케일을 설정할 수 있었다. 이 PR은 통화 매칭 로직이 의존하는 `ResolvedToken.chainId`를 쓰기 위해 새 viem 릴리스에 버전을 고정했다.

이번 변경은 이 브리프가 지난 2주 다룬 ID 증명 체계 구축이나 디스패치 우회 버그 수정보다는 규모가 작고, 이 브리프가 mppx를 다루는 것도 세 번째 연속 호다. 세 건 모두 같은 패턴이다 — 새 기능이 아니라, 기존 결제 표면을 그 자리에서 단단하게 다지는 작업이다.

## 왜 중요한가

오늘 세 소식 중 어느 것도 x402 백서나 AP2 발표 같은 의미의 프로토콜 출시는 아니다. 셋 다 검색 결과든 정책 읽기든 결제든, 에이전트가 직접 요청하는 쪽을 이제 기본값으로 설계하기로 각자의 시점에 결정했을 뿐이다. 그중 구글의 결정이 가장 무게를 갖는다. MCP 서버는 거버넌스 표면 자체를 에이전트가 호출할 수 있게 만들었지만, 거기서 다스리는 대상은 에이전트가 가동되기 전 어떻게 설정되는지이고, 가동 중인 에이전트의 개별 호출이 무엇을 할 수 있는지는 아니다. 실행 시점 권한 부여라는 그 두 번째 문제는 x401, FIDO의 에이전트 작업, 옥타의 Cross App Access가 따로따로 씨름하고 있는데, 이번 주에는 그쪽에서 아무것도 나오지 않았다. 브레이브와 mppx는 같은 내기를 더 작은 규모로 걸었다. 한쪽은 계정 없이 호출당 결제, 다른 쪽은 통화 버그를 잡아내는 타입이다.

## 지켜볼 신호

- 브레이브의 웹·뉴스·이미지·영상 엔드포인트가 실제로 x402 요율로 옮겨가는지, 그리고 오늘 출시의 베이스 전용·가스 보조 조건이 언제 바뀌는지.
- 구글이 MCP 서버의 GA와는 별도로 자연어 커스텀 제약의 상태(GA 또는 프리뷰)를 명시하는지.
- 이번 주 열려 있는 UCP PR들(판매자 귀속 정보, 결제 수단의 결제자 식별, WebMCP 전송 바인딩) 중 하나라도 실제로 머지되는지.
- 네 번째 연속 호에서도 날짜가 확인된 소식이 없는, 마스터카드의 "11월 중 미국 발급사 전체 적용"이라는 어전트 페이 주장.

## 한계

브레이브 블로그 글이 링크한 자체 API 문서는 이번 조사에서 직접 확인하지 않았다. 따라서 LLM Context 외 엔드포인트가 오늘 실제로 x402 아래 서비스되는지, 아니면 글의 미래 시제 표현대로 아직 대기 중인지는 이 브리프로는 확인할 수 없다. UCP의 이번 주 PR 10여 건은 제목과 상태만 확인했고, 어느 것도 이번 주 안에 머지되지 않았기에 내용까지 대조하지는 않았다. x402-foundation/x402 저장소의 이번 주 활동은 버전 올리기와 주석 정리 PR에 그쳤고, 보고할 만한 기능이나 스펙 변경은 없었다.
