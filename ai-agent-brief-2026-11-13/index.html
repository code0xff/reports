What moved

Brave's Search API starts taking payment per request over x402

Brave's LLM Context endpoint, the one built for agents to ground answers, now returns an HTTP 402 to an unauthenticated request instead of demanding an API key[1]. The response states a price; a client signs a USDC payment on Base for that amount and retries, and the search runs after the payment verifies, with a transaction receipt attached to the response. Brave runs its own facilitator for the verification step instead of routing through a third party. The post recommends Purl, Stripe's CLI wallet, as the client side of that flow[1].

The rollout is a live launch, not a pilot, but it is narrower than the headline: Base and USDC are the only chain and stablecoin supported today, with others "incoming soon," and gas on Base is covered only "for a limited time"[1](vendor-stated). Brave's post says its web, news, image, video, and local endpoints will also move to the $0.005-per-request x402 rate, in future tense — whether that has shipped yet is not stated. Brave joins You.com and Linkup, both of which already answer a bare request with x402's 402 challenge; Exa and Parallel, per third-party reviews, are still on API keys. The HN thread that surfaced the story drew no comments, which for a protocol this brief has tracked since its first edition is itself notable: an agent-payments integration from a mainstream search brand didn't register as news to the people who'd be building against it.

Google Cloud takes the Organization Policy MCP server to GA

Google Cloud announced general availability for its Organization Policy MCP server on 2026-11-13, giving "autonomous agents and pipelines" direct tool calls: list constraints, read effective policy with inheritance resolved, create a policy or custom constraint, instead of routing governance work through the console or the REST API by hand[2]. Paired with it: admins can now write custom constraints in plain language via Gemini, with two of the worked examples specifically about agents — require agent-identity on Agent Runtime, and require that any agent deployed there use an approved Agent Gateway[2].

What this ships is deployment-time governance, not runtime authorization. The constraints decide how an agent is configured and identified before it runs; they say nothing about what a specific tool call is allowed to do once the agent is live, which is the harder and more contested problem the identity-and-authorization standards on this beat (x401, FIDO's agent work, Okta's Cross App Access) are trying to solve from the other direction. Google's MCP server is notable mainly for making a cloud governance surface itself agent-callable — the same shift from "a human configures this" to "an agent configures this" that keeps showing up across today's three items.

mppx unifies how it reads a currency

Pull request #1275, merged into mppx on 2026-11-12, replaces a handful of ad-hoc currency-handling paths with one Currency type that accepts a raw address, a viem Token, or a ResolvedToken interchangeably across the Tempo client, the Tempo server, x402's asset list, and the EVM server methods[3]. The concrete bug this closes: before the change, a token's decimals had to be assumed instead of read from the token itself, so a token from the wrong chain could silently set the wrong scale for an amount. The PR pins a new viem release to get ResolvedToken.chainId, which the currency-matching logic depends on.

It is a smaller change than the identity-attestation buildout or the dispatch-bypass fix this brief covered the past two weeks, and it is the third straight window with an mppx entry. The pattern across all three is the same: an existing payment surface getting hardened in place, not a new capability.

Why it matters

None of today's three items is a protocol launch in the x402-whitepaper or AP2-announcement sense. Each is an existing system deciding, on its own schedule, that an agent asking directly for a search result, a policy read, or a payment is now the default request to design for. Google's version of that decision is the most consequential: its MCP server makes a governance surface itself agent-callable, but what it governs is how an agent is configured before it runs, not what a live agent's individual calls are allowed to do. That second problem, runtime authorization, is still being fought over separately by x401, FIDO's agent work, and Okta's Cross App Access, none of which shipped anything this window. Brave and mppx made smaller versions of the same bet: pay-per-call pricing with no account on one side, a type that catches a currency bug on the other.
