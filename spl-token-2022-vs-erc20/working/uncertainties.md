# Uncertainties

- **Token-2022 adoption breadth (c18):** PYUSD is a strong, well-documented production example, but the broader share of supply/issuers using Token-2022 vs the original SPL Token is not quantified here. Treat "widely adopted" claims cautiously; PYUSD is a concrete example, not a market-share measurement.
- **Confidential transfers (c11):** The mechanism hides transfer amounts and balances, not account addresses. The underlying primitive is Solana's ZK ElGamal proof machinery; the official page does not use the literal phrase "homomorphic encryption," so avoid over-claiming the cryptographic technique.
- **Systemic-risk framing (c03):** Interpretive. The "one shared program = systemic risk / universal audit benefit" argument is a reasonable trade-off framing supported by technical writers (Blueshift, Thogiti) and Solana's own EVM→SVM docs, but it is an analytical stance, not a measured outcome.
- **Blueshift source metadata (s23/s24):** Course page without explicit author/date; year estimated as 2025. Used as trust-3 technical writing, corroborated by other sources.
- **"Not part of the ERC-20 standard" (c15/c16):** These are absence claims about the EIP-20 standard. They are well grounded in the EIP-20 text (which defines no fee/freeze), but absence is argued from the canonical spec rather than proven exhaustively.
- **Extension composability limits (added in critique):** Community/audit sources report that some Token-2022 extensions cannot be combined (e.g. ConfidentialTransfer + TransferHook, since hooks need the amount that confidential transfers hide) and that venues restrict extensions like PermanentDelegate via whitelists (Orca's TokenBadge). These specifics could not be pinned to a stable verbatim quote, so the draft states the integration-burden point generally and cites the Neodyme footgun analysis (s36) instead of asserting the exact incompatibility matrix.
