AI agents, developer tools, and agent payments — daily brief, 2026-10-21

Money20/20 puts three agent-payment pilots live while x402's own paywall turns out to be bypassable

Abstract

Money20/20 landed in Las Vegas this week, and three different companies used it to turn an agent-payment pitch into something running: Mastercard opened developer access to Agent Pay for Machines and showed nine x402-settled payments flowing through it at Cloudflare Connect[1][2], Visa paired with BILL and Billtrust to put a live invoice-paying agent on a supplier portal with no shared login[2], and Circle and Proof demoed an agent paying a merchant in USDC only after producing a credential that a human had approved the purchase[3]. None of the three moves who is allowed to spend; each keeps a signed mandate as the thing an agent executes rather than decides. Away from the conference, Figma expanded its MCP integrations to twenty new partners the same week its own co-founder called MCP "not a perfect protocol"[4], and a cluster of GitHub disclosures showed that x402's own reference paywall — the thing enforcing payment before access — can be walked around with a stray %2f or %2e%2e in the URL, in both the TypeScript and Java implementations, with fixes still open and unmerged[5][6][7][8].

What moved

Money20/20 turns three agent-payment pitches into pilots

Mastercard used the week to open developer access to Agent Pay for Machines (buyer- and seller-side APIs, a toolkit, a sandbox) eighteen weeks after announcing the product in June[1]. The access follows pilots with six firms: Cloudflare, Ant International, BVNK (which Mastercard acquired in August), AIsa, Base, and Coinbase, with Coinbase Developer Platform supplying wallet infrastructure and Base handling onchain settlement. At Cloudflare Connect, an agent working for a marketing firm bought social-media research and eight campaign images from two providers — nine payments settled over x402, inside a fixed budget[1]. The Block's own framing matters here: Mastercard still calls this a pilot, not a commercial launch.

Visa's version skips the demo stage. Visa, BILL, and Billtrust say they have a live pilot running real transactions: a BILL payment agent registers through Visa's Trusted Agent Protocol and Agentic Directory, then authenticates itself to a Billtrust supplier portal to pay invoices the buyer already approved — no shared credentials, no CAPTCHA (vendor-stated)[2]. The agent has no say in whether to pay; per the companies' own FAQ, it only executes payments a human already authorized. That's the same boundary Mastercard and Circle/Proof both drew this week, which is the one thing all three pitches agree on even while competing on everything else.

Circle and Proof's demo adds the piece neither Mastercard's nor Visa's version foregrounds: proving who approved the purchase, not just that a payment is authorized. Their Money20/20 showcase has an agent present a Proof-issued credential, checked against Proof's published keys, before paying a merchant in USDC from a Circle Agent Wallet — with the merchant's identity check running over a separate protocol called x401 (vendor-stated)[3]. x401 is new to this beat; nothing in the site's prior coverage of the identity layer names it, and no independent source in this window defines its relationship to the Trusted Agent Protocol or to AP2's mandate scheme.

Figma keeps building on a protocol its own co-founder calls imperfect

At Figma's first Config conference, held in India, co-founder Dylan Field told TechCrunch flatly: "I also think that MCP is not a perfect protocol"[4]. He said it favors frontier AI labs and has real room to improve, then announced twenty new MCP integration partners, including Amp, Linear, Notion, and Mistral, and reversed an earlier refusal to support Pi after one of MCP's own co-creators had publicly criticized Figma for the gap. Field's stated reason for not opening Figma's data further isn't technical: more data through MCP means more surface for misuse, even though he says most users have no malicious intent. Read against the expansion announced in the same breath, the criticism looks less like a rejection of the protocol than a public positioning move — Figma wants more say in how its data gets used through MCP, not less exposure to MCP itself.

x402's own paywall turns out to be bypassable

Three GitHub issues filed this window describe the same class of bug hitting different implementations of x402's reference paywall. In the TypeScript/Express middleware, findMatchingRoute decodes %2F and %5C before matching a route, but Express passes the raw path to the handler — so a request to /api/4%2f2/premium-content skips the paywall check entirely and still reaches the paid handler[5]. In the Java implementation, .normalize() collapses %2e%2e into .. before path matching runs, letting /public/%2e%2e/private read paywalled content as if it were the free route[6]. A third issue describes a reflected-XSS path: paywall configuration gets serialized into an inline script without escaping <, so a request-derived value can close the script tag and inject arbitrary HTML or JavaScript[7]. One of the Java reports says the team had already told Coinbase through a HackerOne submission before raising it publicly. A fix PR covering both v1 and v2 paywalls across EVM, SVM, and AVM is open, with regression tests included, but as of this writing it hasn't merged[8].

Why it matters

Every protocol pitched at Money20/20 this week assumes the mandate underneath it is sound — that a signed approval from a buyer or a credential from an identity provider is the thing worth checking, and that checking it is enough. The x402 paywall bugs show what happens one layer down from that assumption: the mandate can be perfectly valid and the enforcement code still lets the request through, because the code that's supposed to gate access and the code that's supposed to serve content disagree about what a URL means. Nobody at Money20/20 was pitching a fix for that; it's a separate, boring kind of bug; that's exactly why it survived three implementations before anyone filed it.
